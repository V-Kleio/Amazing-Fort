Build Phase — Setup Guide

Amazing Fort · Amazing-Alex-style furniture placement (editor steps)

The build-phase logic is code-complete (placement state machine, Kid, inventory slot, persistent Arena, rotation ring). What remains is done in the Godot editor: naming collision layers and building the scenes/layouts these scripts drive. Do the steps in order.

Steps
  1. Name the collision layers do first
  2. Build the PlaceableEntity scene (base furniture piece)
  3. Make an EntityData + a FurnitureDraftOption (so furniture flows draft → bar)
  4. Build the Kid scene
  5. Build the InventorySlot scene
  6. Rebuild the Building-phase layout
  7. Wire level_controller (kid_scene)
  8. Run & verify
Collision layer/mask notation: in the Inspector, Collision → Layer and Collision → Mask are grids of numbered boxes. "layer = Furniture(2)" means tick only box 2. "mask = 1,2,4" means tick boxes 1, 2, and 4. The numbers come from Step 1.

1Name the collision layers

Project → Project Settings… → Layer Names → 2D Physics. Set:

Layer #NameUsed by
1GroundArena floor/walls (optional)
2FurniturePlaceableEntity physics body
3KidThe Kid trigger
4ProjectileEnemy projectiles (your teammate's Combat work)
5FurnitureOverlapPlaceableEntity's build-time overlap probe

2Build the PlaceableEntity scene

This is the reusable furniture piece. Create it at res://entities/placeable/placeable_entity.tscn.

  1. Scene → New Scene → Other Node → RigidBody2D as root; rename to PlaceableEntity.
  2. Build this tree (names must match exactly):
PlaceableEntity (RigidBody2D) <- attach placeable_entity.gd ├ Sprite2D (Sprite2D) ├ CollisionShape2D (CollisionShape2D) physics shape └ OverlapArea (Area2D) build-time overlap probe └ CollisionShape2D (CollisionShape2D) slightly larger than the body shape

Root PlaceableEntity (RigidBody2D) properties

PropertyValue
RigidBody2D → FreezeOn
RigidBody2D → Freeze ModeKinematic
RigidBody2D → Gravity Scale0
CollisionObject2D → Input PickableOff (unchecked)
Collision → Layerbox 2 only (Furniture)
Collision → Maskboxes 1, 2, 4 (Ground + Furniture + Projectile)

Sprite2D + body CollisionShape2D

  • Sprite2D → Texture: drag assets/visual/dummy/ball_dummy.png (placeholder); set Transform → Scale = (0.15, 0.15) to match the project's other art.
  • CollisionShape2D → Shape: New RectangleShape2D (or Circle) sized to roughly cover the visible sprite.

OverlapArea (Area2D) — the build-time overlap probe

PropertyValue
Area2D → MonitoringOn
Area2D → MonitorableOn
Collision → Layerbox 5 only (FurnitureOverlap)
Collision → Maskboxes 1, 3, 5 (Ground + Kid + FurnitureOverlap)
its child CollisionShape2D → Shapesame kind as the body shape, ~2px larger (a small "skin")
Why the extra layer: the OverlapArea (layer 5) sees other pieces' overlap areas + the Kid + the ground, but its mask deliberately excludes Furniture(2) so it never trips on its own body. "No overlap" then guarantees the solid bodies won't interpenetrate when your teammate unfreezes them in Combat.
  1. Select the root → Attach Script → Load → res://entities/placeable/placeable_entity.gd.
  2. Save as res://entities/placeable/placeable_entity.tscn.
More furniture types: duplicate this scene (FileSystem → right-click → Duplicate), swap the Sprite2D texture + both collision shapes, and assign a different EntityData (next step). The placement/inventory/Kid code needs no changes.

3Make an EntityData + a FurnitureDraftOption

Furniture reaches the Build bar through the draft: a FurnitureDraftOption points at your placeable scene.

  1. EntityData: FileSystem → right-click res://data/entities/ → Create New → Resource… → EntityData. Set e.g. mass=2, friction=0.7, bounciness=0.1, durability=100, can_rotate=On. Save as data/entities/couch_cushion.tres.
  2. Open placeable_entity.tscn, select the root, and in the Inspector set Data = your EntityData .tres. Save. or set Data on each duplicated furniture scene
  3. FurnitureDraftOption: right-click res://data/draft/options/ → New Resource → FurnitureDraftOption. Set: display_name, icon (e.g. ball_dummy.png), quantity = e.g. 3, and Entity Scene = entities/placeable/placeable_entity.tscn. Save as data/draft/options/couch_cushion_draft.tres.
Existing dummy furniture options have an empty entity_scene — they simply won't appear as slots in the bar. Only options whose entity_scene is set produce a placeable slot.

4Build the Kid scene

Create res://entities/kid/kid.tscn.

Kid (Area2D) <- attach kid.gd ├ Sprite2D (Sprite2D) bocil_dummy.png, scale (0.15, 0.15) ├ CollisionShape2D (CollisionShape2D) RectangleShape2D (a box) └ AudioStreamPlayer2D (optional)
Node / PropertyValue
Kid (Area2D) → MonitoringOn
Kid (Area2D) → MonitorableOn (so furniture can't be placed on the Kid)
Kid → Collision → Layerbox 3 only (Kid)
Kid → Collision → Maskbox 4 only (Projectile)
Sprite2D → Texture / Scaleassets/visual/dummy/bocil_dummy.png / (0.15,0.15)
CollisionShape2D → ShapeRectangleShape2D covering the sprite
(optional) hurt_sound on the rootassign an AudioStream; needs the AudioStreamPlayer2D child
Attach res://entities/kid/kid.gd to the root, save.

5Build the InventorySlot scene

The bar item widget. Create res://scenes/phases/build/inventory_slot.tscn.

InventorySlot (Button) <- attach inventory_slot.gd ├ Icon (TextureRect) └ Count (Label)
  • InventorySlot (Button): Custom Minimum Size ≈ (140, 140).
  • Icon (TextureRect): anchors Full Rect; Expand Mode Ignore Size; Stretch Keep Aspect Centered.
  • Count (Label): anchor bottom-right; font size ~28. Its text is set at runtime.
  • Attach scenes/phases/build/inventory_slot.gd; save. (The script auto-sets the children to click-through, like DraftCard.)

6Rebuild the Building-phase layout

Open res://scenes/phases/building_phase.tscn and reshape it into:

BuildingPhase (Node2D) <- keeps building_phase.gd └ CanvasLayer └ Control (full rect, Mouse Filter = Ignore) ├ InventoryBar (HBoxContainer) anchored bottom, Mouse Filter = Stop ├ PlayButton (Button) text "Play", Mouse Filter = Stop └ DeleteButton (Button) text "Delete", Mouse Filter = Stop (starts hidden)
  1. Select Control → Anchors Preset Full Rect → Mouse Filter = Ignore (so world taps reach the placement controller).
  2. Delete the old PhaseLabel and ContinueButton (removing the old [connection]).
  3. Add InventoryBar (HBoxContainer): Anchors Preset Bottom Wide; give it some height/offset from the bottom; Alignment = Center; Theme Overrides → Constants → Separation ≈ 16; Mouse Filter = Stop.
  4. Add PlayButton (Button, text "Play"), e.g. top-right; Mouse Filter = Stop.
  5. Add DeleteButton (Button, text "Delete"), near Play; Mouse Filter = Stop. (Leave visible; the code hides it until a piece is selected.)
  6. Select the root BuildingPhase → Inspector → Inventory Slot Scene = scenes/phases/build/inventory_slot.tscn.
  7. Save.
Node names InventoryBar, PlayButton, DeleteButton under CanvasLayer/Control must match exactly — the script reads those paths.

7Wire level_controller

  1. Open res://scenes/level_controller.tscn, select the Level root.
  2. Inspector → Kid Scene = entities/kid/kid.tscn.
  3. (Optional) Arena Bounds Scene = a StaticBody2D floor/walls scene (layer Ground(1), mask empty). Leave empty for now if you don't have one.
  4. Save.
The Arena is created in code as a persistent sibling of PhaseContainer; the Kid is spawned into it once at bottom-center (960, 980). It survives the Build→Combat swap so your teammate's Combat phase can find placed furniture + the Kid via get_tree().get_nodes_in_group("placeable") and "kid", then call PlaceableEntity.activate_physics() on each piece.

8Run & verify

  1. F5 → main menu → Start → skip/finish tutorial → draft your furniture option → Build phase.
  2. The bottom bar shows a slot (icon + count = quantity). The Kid sits at bottom-center.
  3. Press & hold a slot → a piece appears above the finger and follows it (upward offset).
  4. Drag over the Kid or another piece → it turns red; release → it stays held. Move to open space → green → release → it places; the slot count drops by 1; a dotted rotation ring appears and the Delete button shows.
  5. Drag around the ring → the piece rotates (free). Drag the piece body → move it. Tap Delete → piece removed, count restored.
  6. Tap empty space → deselect. Bar/Play taps never spawn or move world pieces.
  7. Press Play → Attacking loads; placed pieces + Kid persist (they're under the Arena). The Build UI + ring are gone.
Optional — test the Kid hit path (Combat is your teammate's job, but you can smoke-test): temporarily make a RigidBody2D, put it in group &"enemy_projectile", set its collision layer to Projectile(4), and drop it onto the Kid at runtime → GameManager.player_health drops by 1, the Kid flashes red, the projectile is freed, and at 0 HP the game ends.
Desktop vs touch: the placement code handles mouse events, which also fire from touch (the project's default emulate_mouse_from_touch). So mouse testing on desktop mirrors on-device touch.
