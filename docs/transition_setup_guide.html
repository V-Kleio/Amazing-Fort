Build → Attack Transition — Setup

Amazing Fort · the animated "DEFEND YOURSELF!" splash

The transition logic is code-complete (scenes/ui/defend_transition.gd): it covers the screen, slams its parts in, holds, fades out, and signals the level to swap Build→Attack behind it. You just build the scene from your art parts and point the level at it. The delete-button follow and the furniture-physics fix are pure code — no editor steps for those.

Until you build & assign the transition scene, the game still works — it just skips straight to the attack phase (with furniture physics correctly activated). So this is safe to do whenever.

1Drop in the art parts

Put the split PNGs in res://assets/visual/transition/ (any names). Typical parts, matching your mock:

  • Background — the full-screen backdrop (yellow striped room). Must cover the whole 1920×1080 (it hides the phase swap).
  • Triangle — the pink shape behind the text.
  • Title — the "DEFEND YOURSELF!" lettering.
  • Character — the angry blue kid.
  • SpeechBubble — the "I'm gonna kill you" bubble.

2Build the transition scene

Create res://scenes/ui/defend_transition.tscn.

  1. Scene → New Scene → Other Node → CanvasLayer root; rename to DefendTransition. Set Layer = 80 and Process → Mode = Always (the script also sets these, but setting them here is tidy).
  2. Build this tree — names must match exactly (the script looks them up; any part you omit is simply skipped):
DefendTransition (CanvasLayer, Layer 80) <- attach defend_transition.gd └ Root (Control, Full Rect) <- the fade target ├ Background (TextureRect, Full Rect, opaque) ├ Triangle (TextureRect) ├ Character (TextureRect) ├ Title (TextureRect) "DEFEND YOURSELF!" └ SpeechBubble (TextureRect) "I'm gonna kill you"
  1. Assign each part's texture. Position/size them where you want the final composition to sit.
  2. Attach res://scenes/ui/defend_transition.gd to the DefendTransition root. Optionally assign Impact Sfx.
  3. Save.
NodeProperty notes
BackgroundAnchors Preset Full Rect; must be opaque and cover the screen (it hides the Build→Attack swap that happens behind the curtain).
Title / Triangle / SpeechBubbleSize the TextureRect roughly to its art (enable Expand or set the node size) so the scale "slam"/pop pivots on the art's center.
CharacterNo size requirement — it slides in from the left (position-based), so any size works.
You don't wire any signals in the editor. The script animates everything and emits covered / finished which the level listens for. Tapping during the splash skips to the fade-out.

3Point the level at it

  1. Open res://scenes/level_controller.tscn, select the Level root.
  2. Inspector → Transition Scene = scenes/ui/defend_transition.tscn.
  3. Save. Done — pressing Play in the Build phase now plays the splash, swaps to Attack behind it, then starts combat.

4(Related) Anchored furniture in combat

The physics fix is automatic: every placed piece now falls, collides, and gets knocked by projectiles when combat starts. To make a specific piece stay fixed (a solid obstacle that doesn't fall), open its EntityData .tres and tick:

  • Anchored In Combat — the piece becomes a static obstacle (projectiles bounce off; it won't fall).
  • (optional) Combat Material Group = hard_material or soft_material — makes the ball bounce harder / softer off this piece (same tags the level's walls use).

Verify

  1. Draft → Build → Play: the splash slams in, holds, fades out; the attack phase is revealed already running. Tapping skips the hold.
  2. On reveal, furniture drops and settles, collides, and reacts to the ball. An Anchored In Combat piece stays put.
  3. In Build, select a piece → the delete icon pops beside it; selecting another moves it; delete refunds the slot.
  4. Remove the Transition Scene assignment → build→attack still works (no splash) and furniture still activates.
