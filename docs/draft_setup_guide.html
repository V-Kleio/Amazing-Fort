Draft Phase — Setup Guide

Amazing Fort · modular draft (furniture / upgrade) selection system

The draft logic is code-complete. What remains is done inside the Godot editor, because it is better done visually: registering the run-inventory autoload, building the two small UI scenes, and authoring the option resources. This guide walks each one click-by-click.

Steps
  1. Register the PlayerInventory autoload required first
  2. Let the editor register the new classes
  3. Build the DraftCard scene (the card UI)
  4. Build the Choosing-phase layout (title + cards row) & assign the card scene
  5. Author draft options as .tres (2 worked examples)
  6. Run & verify
  7. Adding a brand-new draftable type later
Expected until Step 1 is done: the editor shows errors like Identifier "PlayerInventory" not declared. That is normal — the scripts reference the autoload you are about to register. The errors clear after Step 1.

1Register the PlayerInventory autoload

The run-state store that holds everything the player drafts. It must exist as a global singleton.

  1. Project → Project Settings… → Globals tab (a.k.a. AutoLoad).
  2. Path: pick res://autoloads/player_inventory.gd.
  3. Node Name: PlayerInventory exact, case-sensitive
  4. Click Add — it appears in the list with the global toggle enabled.
  5. Close Project Settings.

2Let the editor register the new classes

The new scripts declare global class_names (DraftOption, FurnitureDraftOption, UpgradeDraftOption, DraftPool, DraftCard). Godot registers them on scan.

  1. Click back into the editor window (it rescans on focus).
  2. If errors linger, run Project → Reload Current Project once.
  3. Confirm the bottom Errors/Debugger panel is clean.

3Build the DraftCard scene

This is the visual card, reused for every option. Build it once; the script fills it from data at runtime. Create it at res://scenes/phases/draft_card.tscn.

Create the scene & node tree

  1. Scene → New Scene. In the Scene dock, Other Node → add a Button as root. Rename the root to DraftCard.
  2. Build these children (right-click a node → Add Child Node). Names must match exactly:
DraftCard (Button) <- attach draft_card.gd here └ Margin (MarginContainer) └ VBox (VBoxContainer) ├ RarityBar (ColorRect) ├ NameLabel (Label) ├ IconRect (TextureRect) └ DescriptionLabel (Label)

Set properties

Control → Focus → ModeNone (optional, avoids focus outline)
MarginLayout → Anchors PresetFull Rect

Attach the script & save

  1. Select the DraftCard root → click the Attach Script icon → Load → choose res://scenes/phases/draft_card.gd.
  2. Save the scene: Ctrl+S → res://scenes/phases/draft_card.tscn.
You do not need to set Mouse Filter on any node — the script makes clicks fall through to the Button automatically. The RarityBar color and the name/description text are all filled from the option's data at runtime, so placeholder values in the editor are fine.
Optional polish: give the DraftCard Button a card look via Theme Overrides → Styles → set Normal/Hover/Pressed to StyleBoxFlats (dark background, corner radius ~12). Purely cosmetic; the system works without it.

4Build the Choosing-phase layout

Open res://scenes/phases/choosing_phase.tscn. It currently holds a placeholder label + button. Reshape it into the draft layout the script expects.

Target tree

ChoosingPhase (Node2D) <- keeps choosing_phase.gd └ CanvasLayer └ Control (Full Rect) ├ Background (ColorRect) (optional backdrop) ├ TitleLabel (Label) └ CardsContainer (HBoxContainer)

Edit steps

  1. Select Control → Layout → Anchors Preset → Full Rect.
  2. Rename the existing PhaseLabel → TitleLabel. Set Layout → Anchors Preset → Top Wide; Label → Horizontal Alignment → Center; Font Size → 40. (Its text is overwritten at runtime.)
  3. Delete the existing ContinueButton (this also removes its old signal connection).
  4. (Optional) Add a ColorRect named Background as the first child of Control; Anchors Preset → Full Rect; Color → a dark shade (e.g. #101014).
  5. Add an HBoxContainer named CardsContainer as a child of Control:
    • Layout → Anchors Preset → Full Rect
    • Inspector → Alignment → Center
    • Theme Overrides → Constants → Separation → 32
  6. Select the root ChoosingPhase node. In the Inspector (script variables at the top):
    • Draft Card Scene → drag in res://scenes/phases/draft_card.tscn
    • Offer Count → 3
  7. Save: Ctrl+S.
The cards are instantiated into CardsContainer at runtime, so it looks empty in the editor — that's expected. Tweak spacing/alignment here anytime; it's pure layout.

5Author draft options as .tres

Each card shown is one .tres saved in res://data/draft/options/. The pool auto-discovers everything in that folder — no wiring. Just create the resource and save it there.

How to create one option

  1. In FileSystem, right-click res://data/draft/options/ → Create New → Resource….
  2. Search & pick FurnitureDraftOption or UpgradeDraftOption → Create. Not listed? Redo Step 2 (reload project).
  3. Save it into the options folder with a clear name (e.g. couch_cushion.tres).
  4. Select it and fill the Inspector fields (below), then Ctrl+S.

Fields shared by every option (DraftOption)

FieldMeaning
Display NameCard title.
DescriptionCard body text.
IconCard image — drag a texture, e.g. assets/visual/dummy/bocil_dummy.png.
RarityCommon / Uncommon / Rare / Epic — sets the RarityBar + title color.
WeightRelative chance of being offered (0 = never; higher = more common).

6Run & verify

  1. Press F5. Main menu → Start → complete/skip the tutorial.
  2. The Draft screen shows: title “Round 1 — Choose Your Draft” and a centered row of cards, each with its icon, name, description, and rarity-colored accent bar.
  3. Tap/click a card → the pick is applied and the game advances to Building.

Confirm the inventory handoff (optional)

Open scenes/phases/choosing_phase.gd; inside _on_card_selected, just after option.apply(), add:

print("[Draft] picked ", option.display_name,
    " | furniture=", PlayerInventory.get_items(&"furniture").size(),
    " upgrades=", PlayerInventory.get_items(&"upgrade").size())

Run, pick a card, watch the Output panel — the matching bucket count increases. Remove the print after.

Reset check: lose a run (in Attacking press L) to return to the menu, then Start again — the inventory auto-clears on the new game (round_started(1) → PlayerInventory.reset()).

7Adding a brand-new draftable type later

The payoff: a new content type touches no generic file (not the pool, card, inventory, or phase). Example — a RelicDraftOption:

  1. Create res://data/draft/relic_draft_option.gd: 
    class_name RelicDraftOption
extends DraftOption

@export var relic_effect: String = ""

func get_category() -> StringName:
	return &"relic"

# Optionally override apply() for special behavior, or can_offer() for conditions.
  2. Reload the project (Step 2) so the class registers.
  3. Author .tres instances of it in data/draft/options/ (same as Step 5).

Done. The same DraftCard renders it, DraftPool auto-discovers it, PlayerInventory buckets it under &"relic", and the Draft phase offers it. Read it later with PlayerInventory.get_items(&"relic").
