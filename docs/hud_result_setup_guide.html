Amazing Fort · setup for the three latest changes
Working now with no editor step: the attack reticle is visible (scaled up in code), the hearts show above the Kid (with a drawn placeholder until you add art), and the result screen logic runs. The one required editor step is laying out the result overlay's 2 buttons (Step 1).

1Result overlay — 2 buttons

Open res://scenes/ui/win_screen.tscn and rebuild it as a dimmed overlay with two buttons. The script (win_screen.gd) looks up these exact node paths:

WinScreen (Control, full rect) <- win_screen.gd ├ Background (ColorRect, full rect, e.g. rgba 0,0,0,0.65) └ Panel (PanelContainer, centered) └ VBox (VBoxContainer) ├ ResultLabel (Label) ├ PrimaryButton (Button) <- "Continue" (win) / "Replay" (lose) └ MenuButton (Button) <- "Main Menu"
  1. Root WinScreen (Control), Anchors Preset Full Rect.
  2. Add Background (ColorRect, Full Rect) — a semi-transparent dark so the game shows behind.
  3. Add Panel (PanelContainer or CenterContainer) centered → VBox (VBoxContainer) → ResultLabel, PrimaryButton, MenuButton (names exact).
  4. Remove the old lone ContinueButton/ContentVBox. Save.
Button texts are set by the script (Continue/Replay/Main Menu), so leave them blank or placeholder. Win → Continue advances the round; Lose → Replay restarts the whole run (round 1, health reset); Main Menu exits.

2Kid hearts

The hearts already appear above the Kid (a drawn placeholder). To use real art:

  1. Import your heart PNG (e.g. res://assets/visual/hud/heart.png).
  2. Open res://scenes/level_controller.tscn, select Level, Inspector → Health Heart Texture → assign it.
  3. If the hearts sit too high/low above the Kid, adjust HEARTS_OFFSET in level_controller.gd (currently (0, -420)).
Hearts follow the Kid, persist across build/attack, drop one per hit (with a pop), and refill on a new run. Row size/spacing are exports on the created HealthDisplay (max_hearts 3, spacing 96, heart_size 72) — change the defaults in components/health_display.gd if needed.
